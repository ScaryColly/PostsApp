# Post Free-Text Search - API Contract (Step 2)

## Purpose

This document freezes the API request and response contract for the post free-text search feature before implementation.

It is derived from the acceptance criteria and is intended to be used directly for TDD test authoring.

## Endpoint

- Method: POST
- Path: /posts/search
- Content-Type: application/json

## Request Contract

### Request Body

```json
{
  "query": "posts about docker errors from last week",
  "page": 1,
  "limit": 20,
  "sort": "relevance",
  "filters": {
    "createdBy": "507f1f77bcf86cd799439011",
    "dateFrom": "2026-03-01T00:00:00.000Z",
    "dateTo": "2026-03-17T23:59:59.999Z"
  }
}
```

### Field Definitions

- query: string, required
  - Must contain at least one non-whitespace character.
  - Max length: 500 characters.
- page: integer, optional
  - Default: 1
  - Minimum: 1
- limit: integer, optional
  - Default: 20
  - Minimum: 1
  - Maximum: 50
- sort: string, optional
  - Allowed values: relevance, newest
  - Default: relevance
- filters: object, optional
  - createdBy: string, optional
  - dateFrom: ISO-8601 date-time string, optional
  - dateTo: ISO-8601 date-time string, optional

### Validation Rules

- Missing query, empty query, or whitespace-only query -> 400
- page or limit non-numeric or out of range -> 400
- Unknown top-level properties are ignored (not an error)
- Unknown filters properties are ignored (not an error)
- If dateFrom > dateTo -> 400

## Success Response Contract

### HTTP Status

- 200 OK

### Response Body

```json
{
  "items": [
    {
      "id": "67d5c8d2f1a2b3c4d5e6f123",
      "title": "Fixing Docker Build Errors",
      "content": "If your build fails on npm ci...",
      "createdBy": "507f1f77bcf86cd799439011",
      "image": null,
      "likes": ["507f1f77bcf86cd799439099"],
      "createdAt": "2026-03-15T10:15:00.000Z",
      "updatedAt": "2026-03-15T10:15:00.000Z"
    }
  ],
  "page": 1,
  "limit": 20,
  "total": 42,
  "hasMore": true,
  "meta": {
    "fallbackUsed": false,
    "sortApplied": "relevance",
    "filtersApplied": {
      "createdBy": "507f1f77bcf86cd799439011",
      "dateFrom": "2026-03-01T00:00:00.000Z",
      "dateTo": "2026-03-17T23:59:59.999Z"
    },
    "parsedIntent": {
      "keywords": ["docker", "build", "error"],
      "mustInclude": [],
      "exclude": [],
      "dateFrom": "2026-03-01T00:00:00.000Z",
      "dateTo": "2026-03-17T23:59:59.999Z",
      "createdBy": "507f1f77bcf86cd799439011",
      "sortBy": "relevance"
    }
  }
}
```

### Success Semantics

- items is always present.
- items may be an empty array.
- total is total matching records across all pages.
- hasMore is true when page \* limit < total.
- meta.fallbackUsed is true only when LLM parsing was not used successfully.
- meta.parsedIntent exists in both normal and fallback mode:
  - normal mode: parsed intent after validation/sanitization
  - fallback mode: deterministic keyword intent generated by backend

## Error Response Contract

### 400 Bad Request

Returned when request validation fails.

```json
{
  "error": "Invalid request",
  "details": {
    "query": "query is required",
    "limit": "limit must be between 1 and 50"
  }
}
```

Rules:

- error is a stable high-level message.
- details contains field-level validation messages.

### 500 Internal Server Error

Returned for unexpected backend failures outside standard fallback behavior.

```json
{
  "error": "Failed to search posts"
}
```

Rules:

- No internal stack trace or provider details in response body.

## LLM Parsing Contract (Internal)

The LLM adapter must output strict JSON matching this shape before validation:

```json
{
  "keywords": ["string"],
  "mustInclude": ["string"],
  "exclude": ["string"],
  "createdBy": "string or null",
  "dateFrom": "ISO string or null",
  "dateTo": "ISO string or null",
  "sortBy": "relevance or newest"
}
```

Rules:

- Additional properties are dropped.
- Invalid property types are rejected or sanitized by validator.
- Raw Mongo operators are never accepted from this payload.

## Backward Compatibility

- Existing endpoints under /posts remain unchanged.
- Existing response format for current endpoints remains unchanged.
